F-001 Retry can create duplicate charges Blocker Bug
File: src/payments/retry.tsLine: 44-68Symbol: retryPayment

Problem

The function retries after a timeout without checking whether the provider accepted the first request. A delayed provider response can therefore produce a second charge.

Impact or risk

A customer may be charged twice for one order.

Suggested fix

Send an idempotency key and query the first request before retrying.

Beforets
return provider.charge(input);
Afterts
return provider.charge(input, { idempotencyKey: order.id });
